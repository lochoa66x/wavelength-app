# Validation recovery: implementation and release prompt

Repair the concrete failures preserved in `evaluations/comparative-v1`, keeping the current provider/model configuration and the original captures unchanged. The goal is to deliver supported, useful application content while continuing to reject materially false claims. Passing a validator is not a writing-quality score.

1. Distinguish calendar years from quantities using grammatical context. Accept supported project years in prose and headings. Reject changed years, stitched date ranges, dates borrowed from another named employer/project, changed count units, altered rates and unsupported experience durations. A four-digit number alone must not receive a blanket exemption.
2. Recover clear employment entries after selected/academic project sections without converting project titles, qualifications or training into jobs. Preserve role/employer/date associations, section boundaries and each bullet's own source. Cover unfamiliar occupations, reordered sections, repeated headings and company-first rows.
3. Scope claim checks to their actual assertion. Distinguish supervised tasks from candidate supervision, isolate credentials and their individual status, and distinguish an operational transition from career-change positioning. Retain negative controls for invented leadership, credential upgrades and unsupported career claims. Use the shared contract across generation, edits, readiness and export; invalidate stale assessments when its rules change.
4. Protect content during repair. Restore supported source statements under the correct role, block unfinished empty roles, and retain explicit diagnostics for removals. Do not make a document pass by silently losing useful content or inventing a replacement. Keep the existing human-review packet unrated; do not substitute agent judgments for independent review.

Verification: write regressions before implementation and preserve their initial failures. Replay all six original careers against the revised deterministic checks, keeping live regeneration separate from replay. Freeze ten new fictional career sources before generation, capture their first attempts and internal repairs, then inspect the actual résumé and letter text and downloadable files. Audit factual integrity, useful detail, focus, repetition, professional identity, role completeness, tense, academic/credential status and layout. Record missing outputs and regressions in the denominator; never overwrite a failed attempt with a successful retest.

Run the relevant unit/integration tests, the full suite, build and document-export checks. Investigate failures rather than loosening assertions to get green tests. Commit and deploy the authorized changes when checks pass; verify the deployed revision and application routes. Remove any temporary evaluation entrypoints after capture. Report exactly what improved, what newly failed, what remains untested, and any remaining quality concerns. Do not claim ten live careers when only fixture tests ran.
